1. How does your Navbar update immediately after a name or avatar change without a page refresh? 
Explain which React concept makes this possible.

The React concept is shared state through AuthContext.

The flow is:

AuthContext stores the currently logged-in user's information, such as name and avatar_url.

Navbar reads that user information from AuthContext.

When the profile page successfully updates the name/avatar, it calls updateUser().

updateUser() updates the user state inside AuthContext.

Because React re-renders components when their state/context changes, the Navbar automatically receives the new data and re-renders.

So, there is no need to refresh the page.

In simple terms:

ProfilePage
    ↓
updateUser()
    ↓
AuthContext user state changes
    ↓
React re-renders components using that context
    ↓
Navbar shows new name/avatar

The key concept is React Context + state updates + re-rendering.


2.Why do you verify the current password before allowing a change? What security risk does skipping this step create?

You verify the current password to make sure that the person requesting the password change actually knows the existing password.

For example, suppose someone gets access to a user's logged-in session or token. Without checking the current password, they could potentially do:

PUT /api/me/password
        ↓
Set a new password
        ↓
Original user can no longer log in

That creates a serious account takeover/security risk.

The current-password check adds another authentication factor for this sensitive operation:

if not bcrypt.check_password_hash(
    user['password'], current
):
    return jsonify({
        "error": "Current password incorrect"
    }), 401

So even if someone has the user's authenticated session, they still need to know the existing password to change it.

3.Your password change route returns 401 for wrong current password. Why 401 and not 400?

401 Unauthorized is appropriate because the request failed an authentication/credential check.

The distinction is:

400 Bad Request → The request itself is invalid, such as missing data or passwords not matching.

new_password != confirm_password
→ 400

401 Unauthorized → The supplied authentication credentials are invalid.

current_password is incorrect
→ 401

In this task, the user's current password is being used to verify their identity before performing a sensitive operation. Therefore, a wrong current password is treated as an authentication failure.


4. What is the purpose of the updateUser function you added to AuthContext?

updateUser provides a central way to update the logged-in user's information throughout the React application.

For example, after changing the name:

updateUser({
  name: "Ravi Kumar",
  email: "ravi@example.com"
});

Or after uploading an avatar:

updateUser({
  avatar_url: "/static/uploads/new-avatar.jpg"
});

Because the user data is stored in AuthContext, components such as:

Navbar

ProfilePage

other authenticated components

can immediately see the updated information.

Without updateUser, you might update the database successfully but still have the old user information in React state until the page is refreshed or the user logs in again.
